MV_NXT_PARAM_BT 的 key（不新建表）

一律 DEFAULT_HOLD_*。實際欄名（PARAM_NAME／PARAM_VALUE 等）以現場 DDL 為準，adapter 另寫。

key值誰寫

實際要寫的不是新業務，是翻譯層

抄 adapters/persistence/sqlite/uow.py，改連線與 SQL。Cron／derive／SET／解 Hold 一行都不用為了 Oracle 重寫。現在 load_oracle_factory() 只會丟「尚未實作」。

  1. Factory + UoW：開 oracledb 連線（DSN／wallet 不進 git）；ALTER SESSION SET TIME_ZONE='UTC'；new() 交一個 UoW；commit／rollback；例外時 rollback。兩個 worker 各拿自己的連線。
  2. HoldOrderDao：對 MV_NXT_DEF_HOLD_ORDER_BT 做 get／get_by_key／insert／update／list_open／try_claim。佔位符 :name；時間用 TIMESTAMP WITH TIME ZONE；row_version 對不上就當搶單失敗。SQLite 裡 Default Hold 已在 dh_* 欄，Oracle 同一套欄。
  3. IncidentDao + 寄信欄：對 MV_NXT_DEF_HOLD_INCIDENT_BT。open_or_touch＝同一 (subject, type, episode) 已有就更新次數，沒有才 INSERT。寄信不是另一張表：mail_status／mail_payload 寫在同一列（對應 SQLite 的 outbox 方法）。
  4. SystemControlDao：不建新表。讀寫既有 MV_NXT_PARAM_BT 的 key（DEFAULT_HOLD_MODE 等）。欄位名（PARAM_NAME／PARAM_VALUE…）等看到現場 DDL 再對。這塊獨立實作沒問題。

SQLite 已把 wafer／MES retry／進站去重放進 JSON 欄。Oracle 依樣畫葫蘆即可，不能再 CREATE TABLE。Snapshot 空實作。

DBA 落地

  1. 用 Design/schema/oracle.sql 在空 schema 只建兩張表。
  2. 確認帳號對 MV_NXT_PARAM_BT 有讀寫（不建新表）。
  3. ALTER SESSION SET TIME_ZONE = 'UTC'；字元集 AL32UTF8。
  4. 不要建查案 View 當契約。SQLite 的 v_order_overview 等只給 DEV 查案。

接 Oracle 時一起考慮

  • ORDER／INCIDENT 加欄：sqlite.sql 與 oracle.sql 一起改。禁止 Python ALTER。
  • 主鍵 UUID 由應用層產生，不用 SEQUENCE 當跨 adapter 契約。
  • 先 commit 意圖，再呼叫 MES。網路期間不准長時間 row lock。
  • 告警與待寄信同一列（mail_*）。commit 成功才寄；SENT 就結束通知。
  • 沒 FETCH 到的 MES 欄位不准編造（Created、FirstWaferId）。
  • Hold 查詢 UNKNOWN 不准當成沒有 Hold。現場 MES 一定能回答有／沒有（T25 不跑）。
  • 這套表不是 MES。Hold／Release 真實效果在 HoldPort。
  • 情境庫 SQLite、查案 HTML 不要進生產。
  • 程式已不送 transferHold。actions_json 的 type 只有 SET_HOLD／SET_RELEASE。
